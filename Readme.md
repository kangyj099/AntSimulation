# 개미 시뮬레이션

### ver0.1

2026.02.26 강유진

C++20, 콘솔

---

## 소개

정사각 타일 40×20칸, 콘솔화면에서

화면 1칸 크기의 객체:개미 10체가 움직이는 것을 구경하는 시뮬레이션입니다.

콘솔을 실행시키면 집에 있던 개미들이 밖으로 나와 각자 내키는대로 움직입니다.

돌아다니다가 음식을 만나면 소지할 수 있는 만큼 떼서 집으로 가져갑니다.

집에 먹이를 누적하고, 잠시 쉬고, 다시 나와 움직입니다.

---

## 화면, 조작법 설명

### 화면 표시
개미는 ⓐ, 음식은 F, 집은 H로 표기합니다.

개미의 텍스트 색상은 통상 흰색입니다.

단, 음식을 들고있는 개미는 민트색으로 표시합니다.

화면 하단에는 발생한 주요 이벤트 로그가 출력됩니다.

개미가 집에 드나드는 것, 음식을 주운 것, 집에 음식을 쌓은 결과가 로그로 출력됩니다.

### 클릭으로 음식을 놓아요

왼쪽 마우스 버튼 클릭을 통해 콘솔 화면에 음식을 놓을 수 있습니다.

## 적용 기술

### 멀티스레드

사용자의 입력을 기다리는 동안 시뮬레이션이 멈추는 등의 부정적 간섭을 막기 위해

InputManager에 별개의 Thread를 할당했습니다.

입력 정보는 구조체에 담아 queue에 쌓습니다.

GameManager의 Update주기가 돌아왔을 때 큐에 쌓인 입력 정보를 처리합니다.

효율적이고 안정적인 queue 관리를 위해 더블버퍼 방식을 적용하여

queue 버퍼를 스왑하는 부분과 GameManager에서 queue를 얻어오는 부분으로

크리티컬 섹션을 최소화했습니다.

동기화가 필요한 구간을 { }로 묶어 std::lock_guard를 사용해 보호했습니다.

스레드 안전성을 위해 InputThread 루프 조건으로 std::atomic<bool> 변수를 사용했습니다.

---

### 템플릿

GameObject에 Component를 부착하는 코드에 범용성을 위해 템플릿을 사용했습니다.

구현된 컴포넌트마다 필요한 생성자 매개변수가 다를 수 있기 때문에

가변 템플릿을 사용하여 필요한 인자를 유연하게 전달할 수 있도록 코드를 작성했습니다.

constexpr을 활용해  오브젝트에 부착할 클래스가 Component를 상속한 컴포넌트가 맞는지 확인했습니다.

is_base_of_v를 활용하여 부착하는 컴포넌트가 IUpdate나 IDraw를 상속했는지 컴파일타임에 판단하도록 했습니다.

---

### 이벤트 시스템

시스템간의 결합도를 낮추기 위해서 이벤트 시스템 기반으로 입력처리와 충돌처리를 설계했습니다.

입력 혹은 충돌이 발생할 때, 사건 발생 여부를 판단하는 클래스에서 이벤트를 생성하고 큐에 저장합니다.

게임의 주된 로직을 처리하는 GameManager에서 정해진 타이밍에 쌓인 이벤트를 꺼내 순차적으로 처리합니다.
